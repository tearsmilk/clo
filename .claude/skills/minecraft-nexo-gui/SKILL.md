# Minecraft GUI menus with Nexo

A "custom GUI" on a Paper server is three cooperating pieces:

1. **Background art** - one PNG, drawn 1:1 in GUI pixels, registered as a Nexo **glyph** and placed in the
   inventory **title** (`<white><shift:-8><glyph:menu_id>`). Nexo only draws; it does not create inventories.
2. **Clickable buttons** - normal inventory items in the slots under each painted button, made invisible with
   `item_model: nexo:empty` so the painting shows through, but still giving hover tooltips and clicks.
3. **A menu plugin** (usually DeluxeMenus) that opens the inventory, places those items and runs commands.

Everything in the texture must line up with the 18px slot grid, otherwise the painted button and the slot
that receives the click drift apart. That is why the texture is generated by `scripts/gui_builder.py` from
slot coordinates instead of being painted freehand or by an image model.

## Workflow

### 1. Pin down the menu
Ask only what you cannot infer; sensible defaults in brackets:
- Minecraft + Nexo version [1.21.4+ / latest]; menu plugin [DeluxeMenus]
- Purpose and buttons: label, what it opens/runs, tooltip text
- Rows [6] and layout: big 3x2 tiles for main destinations, 1x1 for back/close/settings
- Theme: frame material (`oak`, `spruce`, `birch`, `stone`, `nether`, `dark`) and colour per button
- Namespace for the pack [server name in lowercase]

Read `references/design-guide.md` before choosing layout/colours - it captures what makes popular server menus
look good (big painted tiles, one hue per destination, vanilla-style frame, honest pixels, short labels).

### 2. Make icons (one per button)
Preferred: an image model + background removal, then let the builder pixel-fit them.
```bash
export POLLI_KEY=sk_...        # Pollinations key from the user; never write it into files or commits
python3 scripts/icon_tools.py gen icons/raw_farm.png "a bundle of golden wheat crossed with an iron hoe"
python3 scripts/icon_tools.py cut icons/raw_farm.png icons/farm.png          # add --fill-holes if a light interior vanished
python3 scripts/icon_tools.py sheet icons/check.png icons/*.png             # look at it before building
```
- Light subjects (parchment, paper, eggs) -> `--bg "dark navy blue"` so rembg does not eat them.
- Other generators work too (Figma `generate_image`, user-supplied PNGs); only the cut step matters.
- A 402 "Insufficient balance" from Pollinations means the free daily credits are used up - tell the user.
- Dependencies: `pip install pillow "rembg[cpu]"` (rembg downloads its model on first use).

### 3. Write the spec and build
A spec is JSON; see `assets/examples/farm_menu/spec.json` for a complete 6-row, 9-tile example.
```json
{
  "id": "hokaria_main", "namespace": "hokaria", "rows": 6, "theme": "oak",
  "title": "Hokaria » Меню фермы", "open_commands": ["menu"],
  "preview_tooltip": "farm", "preview_background": "bg.png",
  "buttons": [
    {"id": "farm", "label": "Ферма", "x": 0, "y": 0, "w": 3, "h": 2, "color": "#5DAA3A",
     "icon": "icons/farm.png", "style": "sunburst",
     "name": "&e&lФерма", "lore": ["&7Сажай и собирай урожай"],
     "commands": ["[close]", "[player] warp farm"]}
  ]
}
```
- `x,y,w,h` are in **slots** (x 0-8, y 0..rows-1). Buttons may not overlap; the builder checks.
- `style`: `sunburst` (default), `gradient`, `flat`. `label` is optional (icon-only 1x1 buttons).
- Labels use the bundled 5x7 pixel font (Latin + full Cyrillic). Fit: ~8 letters on a 3-wide button,
  ~5 on 2-wide; the builder refuses wider labels rather than squeezing letters together - shorten the word.
- Optional: `draw_free_slots` (false hides empty container slots), `title_text` (live text after the glyph),
  `ascent_nudge` / `shift_nudge` (1px corrections after testing in game).

```bash
python3 scripts/gui_builder.py spec.json out/
```
Outputs: `out/texture/<id>.png` (the glyph), `out/preview.png` (in-game look, with tooltip),
`out/preview_grid.png` (slot numbers over the art), `out/Nexo/...` (glyph yml + pack texture, ready to merge into
`plugins/Nexo/`), `out/DeluxeMenus/gui_menus/<id>.yml`, `out/INSTALL.md`.

### 4. Check before handing over
Look at `preview.png` and `preview_grid.png` yourself:
- every button sits exactly on its slots, labels are readable and not touching the tile edge
- icons are recognisable at icon size (if mush, regenerate with a simpler subject)
- nothing important sits where a single 16x16 slot highlight would hide it
Then send the user the preview first (they judge visually), then the files.

### 5. Install notes for the user
1. Merge `out/Nexo/` into `plugins/Nexo/`; copy the DeluxeMenus file and register it in DeluxeMenus `config.yml`.
2. `/nexo reload all` (rebuilds + resends the pack), `/dm reload`, open the menu.
3. If the art is a pixel or two off: adjust `<shift:N>` (horizontal) or the glyph `ascent` (+ moves up), or
   use https://nexomc.com/tools/gui-visualizer. If tags show as raw text use `%nexo_shift_-8%%nexo_<id>%`.

## Beyond chest menus
- Visible custom icons in normal slots (shop items, ranks): make Nexo items with `Pack.texture` and use
  `material: nexo-<item_id>` in DeluxeMenus - see `references/nexo-reference.md` (Items).
- Multi-page menus: one glyph per page + `[openguimenu]`; state variants via `view_requirement` + `priority`
  (`references/menu-plugins.md`).
- Other screens (hopper, dispenser, anvil) and textures > 256px: `references/gui-geometry.md`.
- Forms/settings with inputs: suggest Nexo Dialogs (1.21.6+) instead of a texture menu.
- Bedrock players: Scaffolding addon converts glyph GUIs automatically (approximate alignment).

## What not to do
- Do not ship an AI-generated picture of a whole menu as the texture: models do not respect the slot grid. Use
  such images only as mood boards, then rebuild properly with the builder.
- Do not upscale or anti-alias the texture; Minecraft scales it itself. Keep it 1:1 and <= 256x256.
- Do not hardcode or commit API keys; pass them via environment variables.
